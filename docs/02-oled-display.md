# 任务 02：OLED 显示温湿度与系统状态

> 项目阶段：本地显示。以前一任务“DHT11 采集与 USART1 输出”已稳定工作为前提。本任务保持串口输出，不接加热负载、不做 PID，也暂不接入 FreeRTOS。

## 任务目标

把已通过校验的 DHT11 温湿度数据显示到 OLED，并显示传感器读取状态。出现 DHT11 超时或校验失败时，屏幕明确显示错误状态，不能把上次读数伪装成当前值。

## 开始前记录屏幕信息

先抄录手中 OLED 模块或套件资料上的信息，不要仅凭外形猜测：

| 项目 | 实际信息 |
| --- | --- |
| 屏幕控制器（例如 SSD1306、SH1106） | 待确认 |
| 分辨率（例如 128×64） | 待确认 |
| 接口（I²C / SPI） | 待确认 |
| 模块引脚和供电要求 | 待确认 |
| I²C 7 位地址（若为 I²C） | 待确认 |
| STM32 实际连接的 GPIO / 外设 | 待确认 |

如果屏幕只有 `GND`、`VDD`、`SCK`、`SDA` 四个引脚，通常是 I²C 模块，但仍需对照模块资料确认。`SCK` 常用作 I²C 时钟线（SCL），`SDA` 是数据线。供电电压和地址因模块而异。

## 操作步骤

### 1. 先验证 OLED 硬件与引脚

- 断电后确认屏幕接口、控制器、供电范围和引脚定义。
- 查明 OLED 的 SCL/SDA 实际接到 STM32 哪些引脚；不要直接假设为 I2C1 默认引脚。
- 确认 OLED 与 STM32 共地，且 I²C 上拉电压不会超过 MCU GPIO 的允许电平。
- 暂时不要连接加热片或功率驱动。

**验收：**接线表中的控制器、接口、电源、GPIO 都有模块资料或套件原理图作为依据。

### 2. 配置 I²C 外设

仅当模块确认使用 I²C 时执行：

1. 在 CubeMX 中按实际接线启用对应的 I²C 外设，并开启对应 GPIO 时钟。
2. 先使用 100 kHz 标准模式，生成代码。
3. 编译并下载，确认工程仍能启动，USART1 的 `BOOT OK` 和任务 01 的串口功能仍正常。

如果模块是 SPI 接口，应按模块引脚资料配置 SPI 和片选/复位等信号，不要套用 I²C 步骤。

**验收：**工程可编译、下载，原有 DHT11 与 UART 工程没有被破坏。

### 3. 确认 OLED 地址并做通信测试

I²C 模块先根据资料查地址；若资料不明确，可用 `HAL_I2C_IsDeviceReady()` 对已确认的候选地址做应答测试。STM32 HAL 接口通常要求把 7 位设备地址左移一位传入，例如：

```c
#define OLED_ADDR_7BIT  0x3C  /* 仅为常见示例，须以模块资料/实测为准 */

HAL_StatusTypeDef status =
    HAL_I2C_IsDeviceReady(&hi2c1,
                          (uint16_t)(OLED_ADDR_7BIT << 1),
                          2U,
                          100U);
```

如果模块地址是 `0x3D` 或其他值，应使用实测地址；不要把示例地址当成所有 OLED 的固定地址。若没有应答，先检查供电、共地、SCL/SDA 是否接反、GPIO 复用配置和上拉电平。

**验收：**设备应答测试返回 `HAL_OK`，或通过屏幕驱动成功初始化确认通信正常。

### 4. 单独点亮并显示固定文本

- 选择与控制器和接口匹配的 OLED 驱动；若复用开源驱动，先确认其控制器兼容性和许可证。
- 先实现初始化、清屏、写字符串和刷新。
- 暂时只显示固定内容，例如 `OLED OK`，先验证文字位置、方向和清晰度。
- 避免在每个主循环周期都整屏刷新；按需要更新内容。

**验收：**复位后屏幕能稳定显示固定测试文字，没有花屏、乱码或持续闪烁。

### 5. 接入 DHT11 有效数据

- 只在 DHT11 读取成功且校验通过后更新温湿度字段。
- 成功示例：`T: 25 C`、`H: 58 %`。
- 读取失败时显示 `Sensor Error` 或 `DHT11 Timeout`；不能显示 0，也不能不加标记地保留旧值。
- 保留 USART1 的输出，方便对照屏幕与串口数据。
- DHT11 两次真实采样至少间隔 2 秒；若屏幕刷新更快，显示最近一次有效样本时要明确它是最近一次读数。

**验收：**屏幕与串口上的温湿度一致；传感器失败时屏幕和串口都能显示错误状态。

### 6. 测试并记录

- 连续运行至少 10 分钟，检查是否花屏、死机或 UART 输出异常。
- 暂时断开 DHT11 DATA，确认屏幕报告错误，程序其他功能仍运行。
- 恢复 DATA，确认读数能恢复。
- 记录屏幕型号、接口、引脚、I²C 地址、驱动来源、成功/失败现象和测试时长。

## 文件建议

把显示驱动与业务显示接口分开，便于后续改成 FreeRTOS 任务：

```text
Core/
  Inc/
    oled.h          # 对外接口
    oled_font.h     # 字模（若需要）
  Src/
    oled.c          # OLED 初始化和底层写入
    oled_font.c     # 字模（若需要）
    app_display.c   # 温湿度和状态的界面更新
```

文件名可按当前 CubeMX 工程风格调整。DHT11 驱动继续只负责采集和校验；OLED 代码负责显示，不要把整个显示实现塞进 DHT11 驱动。

## 完成标准

- [ ] 已确认屏幕控制器、接口、供电、GPIO 和地址
- [ ] OLED 能显示固定测试文本
- [ ] 能显示校验通过的温湿度
- [ ] 读取失败时明确显示错误状态，不伪造或误标旧数据
- [ ] UART 仍正常，连续运行 10 分钟无死机
- [ ] 接线和测试结果有记录
- [ ] 没有上传公司资料或未经确认的屏幕/套件内部资料
