# 软件架构

## FreeRTOS 任务设计

| 任务 | 建议优先级 | 周期/触发 | 职责 |
| --- | --- | --- | --- |
| `ProtectionTask` | 高 | 10–20 ms | 检测过温、传感器异常和加热异常；进入故障状态时关闭 PWM。 |
| `TemperatureTask` | 中高 | 10–20 ms | 读取 ADC 或数字传感器，完成温度换算和滤波。 |
| `ControlTask` | 中 | 100 ms | 接收当前温度，执行 PID，更新 PWM 占空比。 |
| `UiTask` | 低 | 100–200 ms | 扫描按键、显示当前温度、目标温度和状态。 |
| `CommTask` | 低 | 事件触发 | 处理 UART 指令并周期性上报运行数据。 |
| `LogTask` | 低 | 500 ms–1 s | 整理日志数据，供上位机分析。 |

具体优先级需要根据 MCU 主频、任务执行时间和测试结果调整；保护功能不应依赖低优先级任务。

## 数据流与同步

```text
TemperatureTask --温度样本队列--> ControlTask --PWM命令--> HeaterDriver
        |                                 |
        +--最新温度快照-------------------+--> UiTask / CommTask / LogTask

ProtectionTask --故障事件标志组--> 所有任务
UiTask / CommTask --参数队列--> ControlTask
```

- 采样任务向队列发送带时间戳的温度样本，避免控制任务读取半更新的数据。
- UI 和通信任务通过参数队列请求修改目标温度或 PID 参数。
- 故障状态使用事件标志组广播；`ProtectionTask` 关闭 PWM 后，其他任务只负责显示和上报。
- OLED、UART 等共享外设由互斥锁保护；中断服务程序内只使用 `...FromISR()` 接口。

## 状态机

```text
INIT -> SELF_CHECK -> IDLE -> HEATING -> HOLD
                      ^       |         |
                      |       +---------+
                      |
FAULT <---------------+---- 任何保护条件触发
```

- `INIT`：完成外设和 RTOS 初始化，默认关闭加热。
- `SELF_CHECK`：确认传感器数据处于合理范围。
- `IDLE`：等待用户启动或设置目标温度。
- `HEATING`：温度低于目标区间，PID 增加输出。
- `HOLD`：进入目标温度附近的稳态控制。
- `FAULT`：锁定 PWM 输出，记录故障码；仅在排除故障并显式复位后离开。

## PID 实现边界

控制周期固定为 100 ms。输出需要限幅到 `0–100%`，积分项需要限幅或采用抗积分饱和策略。调参时至少记录：目标温度、实际温度、PWM 占空比、升温时间、最大超调量与稳态误差。

## 保护策略

- 温度高于软件上限：立即关闭 PWM 并锁定为故障状态。
- 温度传感器超出合理 ADC/数字量范围：判断为断线或短路，关闭 PWM。
- 长时间输出高功率但温升异常：记录加热异常，进入故障状态。
- 看门狗：用于软件跑飞后的恢复，不能替代独立硬件过温保护。
