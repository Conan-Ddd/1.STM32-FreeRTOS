# 任务 01：STM32 读取 DHT11 并通过串口输出

> 项目阶段：基础采集。此任务先不接加热片、不启用 PID，也不要求 FreeRTOS。先把传感器通信和串口调试做稳定，再进入多任务阶段。

## 任务目标

使用江科大 STM32 套件读取 DHT11 温湿度模块，将温度、湿度和读取状态持续输出到电脑串口终端。遇到通信超时或校验失败时输出错误状态，而不是沿用上一次读数冒充新数据。

完成后应留下可编译的个人工程、接线记录和测试记录；不要上传实习公司的设计文件、固件或测试数据。

## 开始前需要确认

请先填写，**不要在未确认芯片型号和模块电平前照搬其他人的引脚配置**：

| 项目 | 你的实际情况 |
| --- | --- |
| 开发板上的 STM32 完整型号 | STM32F103C8T6 |
| 使用的开发环境及版本（Keil / STM32CubeIDE 等） | Keil5，VScode，STM32CubeMX |
| 下载器或板载调试器 | ST-Link |
| DHT11 模块 VCC、DATA、GND 的丝印 | VCC,DAT,GND |
| DHT11 模块允许的供电和 DATA 高电平 | 3.3-5V,3.3V|
| DATA 所接 STM32 GPIO | PB1 |
| 串口 TX/RX 所接引脚及波特率 | PA9,PA10,115200 |
| 模块是否已有 DATA 上拉电阻 | 有 |

DHT11 芯片资料给出的供电范围为 3.5–5.5 V、采样间隔大于 2 秒，DATA 为单总线信号。不同商家的“三针模块”可能带稳压、上拉或电平转换，必须查看手中模块的标注或资料。**如果 DATA 被上拉到 5 V，不要在未确认该 STM32 引脚耐压/电平转换方案前直接接入 GPIO。**开发板与传感器必须共地。

## 硬件连接

1. 断电后辨认模块丝印，再接 VCC、GND、DATA；不要仅凭线材颜色判断。
2. 将 DATA 接到你选定的、可作输入/输出切换的 GPIO。记录具体端口和引脚。
3. 按模块资料核对供电与上拉电平；需要时使用合适的电平转换。
4. 连接开发板与电脑，确认下载和串口功能正常。
5. 此阶段不要接 MOSFET、加热片或高功率电源。

## 开发步骤

### 1. 建立最小工程

- 按开发板实际 STM32 型号建立新工程。
- 先实现 LED 闪烁或串口输出 `BOOT OK`，确认编译、下载、时钟和串口都正常。
- 串口终端参数与工程一致，建议先用常见的 115200、8N1；这是项目选择，不是 DHT11 的通信速率。
- 保存工程配置和接线表，确保下次可以重复构建。

**验收：**复位后，串口能稳定输出启动信息，不出现乱码。

### 2. 实现 DHT11 底层驱动

- 上电后先等待传感器稳定，再发起第一次读取。
- 主机将 DATA 拉低至少 18 ms，随后释放总线并等待传感器响应。
- 使用硬件定时器或可靠的微秒计时读取 40 位数据；不要用未经校准的空循环“猜”时序。
- 每一个等待电平变化的环节都设置超时，避免传感器拔掉后程序永久卡住。
- 读取 5 字节后校验：前 4 字节之和的低 8 位应等于第 5 字节。
- 区分成功、响应超时、数据超时、校验失败等结果。

**验收：**成功读取合理的温湿度；拔掉 DATA 后程序仍持续运行，并报告失败。

### 3. 串口输出固定格式

建议每隔 **至少 2 秒**尝试读取一次；为了调试稳定，可先设为 3 秒。成功示例：

```text
time_ms,temp_c,humidity_pct,status
3000,25,58,OK
```

失败示例：

```text
6000,,,TIMEOUT
```

不要把失败样本写成 `0°C` 或继续显示旧值为“当前值”。若保留上次有效值，需同时标注 `STALE` 和上次成功时间。

**验收：**串口输出字段顺序固定；连续运行 10 分钟无死机和明显乱码。

### 4. 做简单测试

- 室温静置：观察读数是否处于合理范围、是否持续变化。
- 手靠近传感器但不触碰裸露电路：观察温度/湿度变化趋势。
- 暂时断开 DATA：确认出现超时，主循环仍运行。
- 恢复 DATA：确认系统可重新读到有效数据。
- 记录连续运行时间、成功读取次数、失败次数和失败类型。

DHT11 测量空气温湿度，本任务只验证采集链路。不要用它贴在加热片上，也不要把这一阶段描述为“完成恒温控制”。
